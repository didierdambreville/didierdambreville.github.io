Ni ++ ni -- : n += 1. Puissance : 2_i32.pow(10), x.powf(0.5), x.sqrt(). Arrondis : round, floor, ceil · bornes : min, max, clamp · reste positif : rem_euclid (-7 % 3 → -1). ! Flottants : comparer (a - b).abs() < 1e-9, pas a == b après un calcul.

Tout est expression

let signe = if n < 0 { "négatif" } else { "positif" };

let carre = {
    let a = 3;
    a * a            // pas de ; : valeur du bloc
};                   // carre = 9

Un bloc vaut sa dernière expression sans ; ; avec ;, il vaut (). Les branches d’un if doivent avoir le même type.

Fonctions

fn aire(l: f64, h: f64) -> f64 {
    l * h                           // valeur renvoyée
}

fn diviser(a: i32, b: i32) -> Option<i32> {
    if b == 0 {
        return None;                // sortie anticipée
    }
    Some(a / b)
}

fn saluer(nom: &str) {              // renvoie ()
    println!("Bonjour {nom}");
}
  • Types des paramètres obligatoires ; type de retour après ->.
  • Ni paramètres par défaut ni surcharge : Option, noms distincts, constructeurs.
  • ! fn f() -> i32 { 5; } : le ; fait renvoyer () → E0308.
  • Retour -> ! : la fonction ne revient jamais (panic!, std::process::exit).

Boucles

for i in 0..5 { }                   // 0, 1, 2, 3, 4
for i in 1..=5 { }                  // 1 à 5 inclus
for i in (0..10).rev() { }          // 9 à 0
for i in (0..10).step_by(3) { }     // 0, 3, 6, 9
for (i, x) in v.iter().enumerate() { }

while n > 0 { n -= 1; }

let mut k = 0;
let r = loop {                      // boucle sans fin…
    k += 1;
    if k == 10 { break k * 2; }     // …qui renvoie 20
};

'externe: for x in 0..5 {           // étiquette
    for y in 0..5 {
        if x + y > 6 { break 'externe; }
        if y > x { continue 'externe; }
    }
}

for x in &v parcourt sans consommer ; for x in v consomme v (inutilisable ensuite) ; for x in &mut v permet de modifier : *x += 1.

match : filtrage par motif

match n {
    0 => println!("zéro"),
    1 | 2 => println!("un ou deux"),
    3..=9 => println!("chiffre"),
    x if x < 0 => println!("négatif : {x}"),
    grand @ 100.. => println!("grand : {grand}"),
    _ => println!("autre"),
}

let pays = match code {             // une expression
    'F' => "France",
    'D' => "Allemagne",
    _ => "inconnu",
};

3 · Possession, emprunt, durées de vie

Mémento — Rust

Les trois règles de la possession (ownership)

  1. Chaque valeur a un seul propriétaire : une variable, un champ, un élément de collection.
  2. Affecter la valeur ou la passer à une fonction la déplace (move) : l’ancien nom devient inutilisable.
  3. Quand le propriétaire sort de sa portée, la valeur est libérée (drop), automatiquement : ni ramasse-miettes ni free.

Les types Copy (entiers, flottants, bool, char, &T, tuples et tableaux de types Copy) sont copiés au lieu d’être déplacés. Les autres (String, Vec, Box…) se dupliquent explicitement avec .clone() : une copie coûteuse reste visible.

let s1 = String::from("salut");
let s2 = s1;           // déplacement : s1 n'est plus utilisable

Déplacer, copier, cloner

let s1 = String::from("salut");
let s2 = s1;                        // déplacement
// println!("{s1}");                // E0382 : valeur déplacée

let s3 = s2.clone();                // copie profonde
println!("{s2} {s3}");              // les deux sont valides

let a = 5;
let b = a;                          // i32 est Copy
println!("{a} {b}");                // a reste valide

fn prendre(s: String) { }           // prend possession
prendre(s3);                        // s3 inutilisable ensuite

Emprunter : les références

fn longueur(s: &String) -> usize { s.len() }  // lit
fn crier(s: &mut String) { s.push('!'); }     // modifie

let mut s = String::from("salut");
let n = longueur(&s);               // emprunt partagé
crier(&mut s);                      // emprunt exclusif
Règle d’or — à un instant donné : soit autant de références partagées &T qu’on veut, soit une seule référence exclusive &mut T. Et une référence ne vit jamais plus longtemps que la valeur qu’elle désigne.
let mut v = vec![1, 2, 3];
let premier = &v[0];                // emprunt partagé…
v.push(4);                          // E0502 : exclusif
println!("{premier}");              // …encore utilisé ici

Pourquoi ? push peut réallouer le vecteur : premier désignerait une mémoire libérée. Correctifs : utiliser premier avant le push, ou copier la valeur (let premier = v[0];).

Un emprunt dure jusqu’à sa dernière utilisation, pas jusqu’à la fin du bloc.

Durées de vie ('a)

fn plus_long<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() >= y.len() { x } else { y }
}

struct Extrait<'a> {
    texte: &'a str,                 // la structure emprunte
}
  • 'a ne change aucune durée : il décrit le lien entre les références (ici : le résultat vit autant que la plus courte des deux).
  • Élision : une seule référence en paramètre, ou &self → annotation inutile.
  • 'static : valable pendant tout le programme (littéraux "…").

Portée et libération

{
    let a = String::from("a");
    let b = vec![1, 2, 3];
    // … a et b utilisables ici
}                       // fin de portée : b, puis a, libérés
let v = vec![0; 1000];
drop(v);                // libération anticipée

Ordre inverse de la déclaration. impl Drop : agir à la libération (fermer un fichier, relâcher un verrou).

Structures et méthodes

#[derive(Debug, Clone, PartialEq)]
struct Point {
    x: f64,
    y: f64,

impl Point {
    fn new(x: f64, y: f64) -> Self { // fonction associée
        Self { x, y }                // raccourci de x: x

    fn deplacer(&mut self, dx: f64) { self.x += dx; }

Énumérations

use std::f64::consts::PI;

enum Forme {
    Cercle { rayon: f64 },
    Rectangle(f64, f64),
    Point,
}

impl Forme {
    fn aire(&self) -> f64 {
        match self {
            Forme::Cercle { rayon } => PI * rayon * rayon,
            Forme::Rectangle(l, h) => l * h,
            Forme::Point => 0.0,
        }
    }
}

Une valeur d’énumération est une de ses variantes, chacune avec ses propres données : idéal pour modéliser des états.

Dans le prélude, sans use : enum Option<T> { None, Some(T) } et enum Result<T, E> { Ok(T), Err(E) }. Rust n’a pas de null.

Traits : comportements partagés

trait Decrire {
    fn nom(&self) -> String;         // à fournir
    fn decrire(&self) -> String {    // fournie par défaut
        format!("Je suis {}", self.nom())

}

impl Decrire for Point {
    fn nom(&self) -> String { "un point".to_string() }
}

use std::fmt;
impl fmt::Display for Point {        // active {} et to_string
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

5 · Gestion des erreurs, entrées-sorties

Mémento — Rust

Trois situations

panic!irrécupérable : bogue, invariant violé ; le thread s’arrête
Result<T, E>récupérable : l’appelant décide (fichier absent, saisie invalide, réseau)
Option<T>absence de valeur, sans erreur (recherche vide, champ facultatif)

Ni exceptions ni null : les échecs possibles se lisent dans la signature des fonctions.

Quand paniquer ?

  • Oui : bogue, invariant impossible, tests, prototypes ; expect sur une hypothèse démontrée.
  • Non : tout ce qui vient de l’extérieur (fichier, saisie, réseau, données).
  • Paniques implicites : index hors limites, division entière par zéro, dépassement (debug), unwrap sur None / Err, tranche de str coupant un caractère.
  • Voir la pile d’appels : variable d’environnement RUST_BACKTRACE=1.

L’opérateur ?

use std::error::Error;
use std::fs;

fn lire_nombre(chemin: &str) -> Result<i64, Box<dyn Error>> {
    let texte = fs::read_to_string(chemin)?;  // io::Error
    let n: i64 = texte.trim().parse()?;       // ParseIntError
    Ok(n * 2)
}

fn main() -> Result<(), Box<dyn Error>> {
    let n = lire_nombre("nombre.txt")?;
    println!("{n}");
    Ok(())
}
  • x? : si Ok(v), donne v ; si Err(e), renvoie aussitôt Err(e.into()).
  • Fonctionne aussi sur Option dans une fonction qui renvoie Option.
  • Seulement dans une fonction qui renvoie Result ou Option (sinon E0277).
  • main peut renvoyer Result : une erreur y est affichée (format Debug) et le programme se termine avec un code d’échec.

Définir son type d’erreur

use std::{fmt, io};

#[derive(Debug)]
enum ErreurConfig {
    Absente(String),
    Syntaxe(usize),
    Io(io::Error),
}

impl fmt::Display for ErreurConfig {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            Self::Absente(c) => write!(f, "clé {c} absente"),
            Self::Syntaxe(n) => write!(f, "erreur ligne {n}"),
            Self::Io(e) => write!(f, "entrée-sortie : {e}"),
        }
    }
}

impl std::error::Error for ErreurConfig {}

impl From<io::Error> for ErreurConfig {  // pour ?
    fn from(e: io::Error) -> Self { Self::Io(e) }
}
  • Bibliothèque : type d’erreur précis (enum), pour que l’appelant distingue les cas.
  • Application : Box<dyn Error> suffit souvent.
  • Crates tierces répandues : thiserror (écrit ce code) et anyhow (erreurs d’application, contexte) — à évaluer comme tout code externe.

Threads

use std::sync::{mpsc, Arc, Mutex};
use std::thread;

let h = thread::spawn(|| 6 * 7);
let r = h.join().unwrap();           // 42

let compteur = Arc::new(Mutex::new(0));
let mut poignees = vec![];
for _ in 0..4 {
    let c = Arc::clone(&compteur);
    poignees.push(thread::spawn(move || {
        *c.lock().unwrap() += 1;
    }));
}
for p in poignees { p.join().unwrap(); }
// *compteur.lock().unwrap() vaut 4

let (tx, rx) = mpsc::channel();      // canal
thread::spawn(move || tx.send("message").unwrap());
println!("{}", rx.recv().unwrap());

let v = vec![1, 2, 3];
thread::scope(|s| {                  // threads bornés :
    s.spawn(|| println!("{v:?}"));   // emprunt permis
});
  • Send : transférable à un autre thread · Sync : partageable par référence. Rc ou RefCell entre threads : refusé (E0277).
  • lock() renvoie Err si un thread a paniqué en tenant le verrou (verrou « empoisonné »).
  • ! Le verrou reste pris jusqu’à la fin de la portée du garde : sections courtes. Deux verrous pris dans des ordres différents → interblocage, que le compilateur ne détecte pas.

  • Pour de nombreuses attentes d’entrées-sorties (réseau, serveurs). Pour du calcul : threads.
