Qu’est-ce qu’un Raspberry Pi ?

Un ordinateur monocarte (single-board computer) : processeur, mémoire, réseau et prises tiennent sur une carte de la taille d’une carte bancaire. Il fonctionne sous Linux et démarre sur une carte microSD (ou un SSD). Il s’allume dès qu’on le branche.

  • SoC (system on a chip) : processeur ARM, processeur graphique et contrôleurs réunis sur une puce.
  • GPIO : 40 broches d’entrée-sortie pour piloter LED, capteurs, moteurs (page 6).
  • Raspberry Pi OS : le système officiel, dérivé de Debian (page 3).
  • Le Pico est un microcontrôleur, pas un ordinateur : pas de Linux, un seul programme, écrit en MicroPython ou en C (page 7).

Conseils indicatifs ; prix très variables : à vérifier chez un revendeur agréé.

Allumer, éteindre, redémarrer

  • Éteindre : sudo poweroff, puis débrancher une fois l’activité de la DEL terminée.
  • Redémarrer : sudo reboot.
  • Pi 5 bouton : appui bref → menu d’arrêt (bureau) ou arrêt (Lite) ; deux appuis rapides → arrêt ; appui long → arrêt forcé. Rallumer : un appui.
  • Modèles sans bouton (Pi 4, Zero et plus anciens) : rallumer en débranchant puis rebranchant l’alimentation.

Le matériel pour démarrer

  • La carte et un boîtier (il évite les courts-circuits sur une surface métallique).
  • ! Une alimentation adaptée au modèle, première cause de pannes : Pi 5 USB-C 27 W ; Pi 4 USB-C 15 W (page 2).
  • Une carte microSD : 32 Go au moins avec bureau, 8 Go pour la version Lite.
  • Un lecteur de cartes pour la préparer sur un autre ordinateur.
  • Câble micro-HDMI → HDMI (Pi 4 Pi 5 Pi 500) ou mini-HDMI (Zero), écran, clavier, souris — inutiles si l’on travaille à distance (page 5).
  • Un refroidissement : Active Cooler ou boîtier ventilé pour le Pi 5.
  • En option : câble Ethernet, SSD NVMe et M.2 HAT+ (Pi 5), pile d’horloge RTC (Pi 5).

Premier démarrage, pas à pas

  1. Sur un autre ordinateur, installer Raspberry Pi Imager (raspberrypi.com/software).
  2. Choisir l’appareil, le système (Raspberry Pi OS, en tête de liste), puis la carte microSD.
  3. Personnaliser : nom d’hôte, fuseau et clavier, utilisateur et mot de passe, Wi-Fi, SSH.
  4. Écrire, laisser la vérification aller à son terme, éjecter.
  5. Insérer la carte (étiquette vers l’extérieur), brancher écran, clavier, souris, réseau.
  6. Brancher l’alimentation en dernier : le Pi démarre seul.
  7. Mettre à jour : sudo apt update, puis sudo apt full-upgrade.

Dix réflexes

  1. Une alimentation officielle (ou de qualité égale), jamais un chargeur quelconque.
  2. Éteindre avant de débrancher : sudo poweroff, puis attendre la fin de l’activité de la DEL.
  3. Câbler le GPIO hors tension ; vérifier deux fois avant de rebrancher.
  4. ! Les broches GPIO sont en 3,3 V : jamais de 5 V sur une entrée.
  5. Mettre à jour chaque semaine.
  6. Sauvegarder : une carte microSD finit par s’user (page 8).
  7. Surveiller la température : vcgencmd measure_temp.
  8. Mot de passe solide, clés SSH, aucun port ouvert vers Internet.
  9. Un nom d’hôte distinct par machine : atelier.local, nas.local…
  10. Noter chaque modification (fichier, commande, date) : on aura à la refaire.

Alimentation

Zero 2 Wmicro-USB 2 Aselon l’alimentation
  • Tous les modèles attendent 5,1 V ; aucun ne gère l’USB-PPS.
  • ! Sous-tension : sous 4,63 V (± 5 %), le Pi l’inscrit au journal ; risque de données corrompues → changer d’alimentation et de câble.
  • Le GPIO ne fournit que 50 mA en tout, 16 mA par broche.
  • Disque dur, modem : concentrateur USB alimenté (mais qui ne renvoie pas de courant vers le Pi).
  • Pi 5 éteint : 1 à 1,4 W ; POWER_OFF_ON_HALT=1 dans l’EEPROM → environ 0,01 W.
  • PoE+ (Pi 5) ou PoE (Pi 4) : alimentation par l’Ethernet, avec le HAT correspondant.

Chaleur et refroidissement

  • Le processeur se protège seul : de 80 à 85 °C, les cœurs ralentissent peu à peu ; à 85 °C, processeur et GPU sont bridés. Pas de dégât, mais moins de performances.
  • Pi 5 : ventilateur officiel (Active Cooler ou boîtier) sur la prise 4 broches ; vitesse selon la température : 50 °C → 30 %, 60 °C → 50 %, 67,5 °C → 70 %, 75 °C → 100 % (retour 5 °C plus bas).
  • Une carte montée à la verticale se refroidit un peu mieux.
  • Mesure fiable : vcgencmd measure_temp.

Stockage et démarrage

  • microSD : 32 Go au moins avec bureau, 8 Go en Lite, moins de 2 To ; une carte rapide de marque.
  • SSD USB : démarrage USB sur Pi 4 Pi 5 — plus rapide et plus durable.
  • SSD NVMe (Pi 5) : sur M.2 HAT+, par le connecteur PCIe ; le 500+ en contient un.

Ordre de démarrage (EEPROM, Pi 4 Pi 5)

sudo rpi-eeprom-config --edit
modifier BOOT_ORDER, puis redémarrer
BOOT_ORDER=0xf41

BOOT_ORDER=0xf14
USB, puis microSD, on recommence

Se lit de droite à gauche : 1 = microSD, 4 = USB, 6 = NVMe, 2 = réseau, f = recommencer. Plus simple : raspi-config › 6 › A4 Boot Order.

Accessoires utiles

  • Boîtier officiel (ventilé pour le Pi 5), Active Cooler.
  • M.2 HAT+ : SSD NVMe (Pi 5).

Écrans et son

  • Écran principal sur la prise HDMI0 ; câble micro-HDMI → HDMI (Pi 4 Pi 5 Pi 400 Pi 500), mini-HDMI → HDMI (Zero) ; adaptateur pour DVI, DisplayPort ou VGA.
  • Pi 4 et suivants : deux écrans jusqu’en 4K. Pi 4 : 4K à 60 Hz sur HDMI0 seulement, avec hdmi_enable_4kp60=1.
  • ! Aucun modèle ne sort de vidéo par l’USB-C.
  • Son : par HDMI, USB ou Bluetooth sur tous les modèles ; prise jack 3,5 mm sur Pi 1-4 seulement (niveau ligne : prévoir un amplificateur ou des enceintes alimentées).
  • Sur l’écran, choisir l’entrée HDMI où le Pi est branché.

Raspberry Pi Imager 2

  1. Device : son modèle.
  2. OS : le système conseillé est en tête ; Use Custom pour un fichier image.
  3. Storage : la carte. ! Garder Exclude system drives coché : le support choisi est entièrement effacé.
  4. Customisation : nom d’hôte (lettres, chiffres, tirets) · localisation (une capitale → fuseau, clavier, pays Wi-Fi) · utilisateur (minuscules) · Wi-Fi · SSH par mot de passe ou clé publique · Raspberry Pi Connect.
  5. Write → I understand, erase and write ; laisser la vérification.

Version 2.0.11.1 (août 2026). Sans personnalisation, un assistant pose les mêmes questions au premier démarrage. Pi 4 et suivants, sans autre ordinateur : installation par le réseau — Ethernet branché, maintenir Maj à l’allumage.

Après le premier démarrage

  • Mettre à jour, puis redémarrer.
  • Vérifier le clavier AZERTY, le fuseau et le pays Wi-Fi (sans lui, pas de Wi-Fi).
  • N’activer que les interfaces utiles (SSH, I²C…).
  • Mot de passe faible ? passwd.
  • Noter l’adresse (hostname -I) et le nom (hostname).
  • Prévoir la sauvegarde (page 8).

Passer sur SSD (NVMe ou USB)

  1. Démarrer sur la microSD ; brancher le SSD (M.2 HAT+ sur Pi 5, ou boîtier USB) ; le voir avec lsblk (ou ls -l /dev/nvme*).
  2. Installer Imager sur le Pi (sudo apt install rpi-imager) et y écrire Raspberry Pi OS sur le SSD (ou copier la carte avec SD Card Copier).
  3. sudo raspi-config › 6 › A4 Boot Order : placer NVMe ou USB en tête.
  4. Éteindre, retirer la carte microSD, rallumer.

Chargeur de démarrage déréglé (Pi 4 Pi 5) : Imager › Misc utility images › Bootloader prépare une carte microSD qui lui rend ses réglages d’usine.

cmdline.txt : les paramètres du noyau

  • /boot/firmware/cmdline.txt : paramètres transmis au noyau Linux au démarrage.
  • ! Tout sur une seule ligne : ce qui suit le premier retour à la ligne est ignoré.
  • Paramètres réellement appliqués : cat /proc/cmdline.

Démarrer sans écran (headless)

  1. Dans Imager, remplir nom d’hôte, Wi-Fi (ou prévoir un câble Ethernet) et SSH, de préférence avec sa clé publique.
  2. Insérer la carte, brancher l’alimentation, patienter une à deux minutes.
  3. Depuis l’ordinateur : ssh moi@hôte.local (page 5).
  4. Introuvable ? Liste des appareils de la box, câble Ethernet, orthographe du nom d’hôte.
  5. Puis sudo raspi-config pour le reste ; bureau à distance : Raspberry Pi Connect ou VNC.

Lancer son programme au démarrage

Le plus sûr : un service systemd. Créer /etc/systemd/system/capteur.service (sudo nano …) :

[Unit]
Description=Mon capteur
After=network-online.target
Wants=network-online.target

[Service]
User=moi
WorkingDirectory=/home/moi/capteur
ExecStart=/home/moi/capteur/env/bin/python main.py
Environment=PYTHONUNBUFFERED=1
Restart=on-failure

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reloadrelire les fichiers de service
sudo systemctl enable --now capteuractiver et lancer
journalctl -u capteur -fvoir ce que le programme affiche (print)

Restart=on-failure relance le programme s’il plante ; PYTHONUNBUFFERED=1 fait paraître les print sans retard.

  • Broches 1 et 2 : à l’extrémité opposée aux prises USB (cartes au format standard). En cas de doute : pinout ou pinctrl -p, sur le Pi lui-même.

Deux numérotations : ne pas les confondre

  • Numéro de broche (1 à 40) : la position physique sur le connecteur.
  • Numéro GPIO (ou BCM) : celui du processeur, employé par GPIO Zero, pinctrl et la documentation.
  • Exemple : LED(17) = GPIO17 = broche 11. GPIO Zero accepte aussi "BOARD11" (numéro physique).
  • Broches sans fonction spéciale, idéales pour LED et boutons : GPIO 5, 6, 16, 17, 22, 23, 24, 25, 26, 27.

Brancher une carte d’extension (HAT)

  • ! Pi éteint et débranché : poser un HAT sous tension peut réinitialiser le circuit d’alimentation.
  • Aligner la broche 1 des deux cartes ; soutenir le HAT par des entretoises.
  • Un HAT (ou HAT+) porte une petite EEPROM, lue au démarrage sur GPIO0 et GPIO1 : le Pi se configure seul. Sans elle, ajouter l’overlay indiqué par le fabricant dans config.txt.
  • Vérifier quelles broches le HAT occupe avant d’en câbler d’autres.

Précautions de manipulation

  • Toucher une masse métallique avant de manipuler la carte (électricité statique) ; la tenir par les bords.
  • Ne jamais poser un Pi en marche sur une surface métallique ou au milieu de fils dénudés.
  • Couper l’alimentation avant de câbler, décâbler ou brancher un module.
  • Préférer des fils femelle-mâle et une platine d’essai aux soudures pour les essais.

Règles électriques — avant tout câblage

  • ! Tout est en 3,3 V : une sortie donne 3,3 V ou 0 V ; une entrée ne supporte pas le 5 V (dégât définitif).
  • ! 16 mA au plus par broche, 50 mA pour l’ensemble : une LED se branche toujours avec sa résistance.
  • ! Jamais de moteur, relais ou bobine directement sur une broche : transistor ou carte de commande (page 7).
  • ! Ne jamais relier une broche 5 V ou 3,3 V à la masse : court-circuit.
  • Seuils garantis d’une entrée : « haut » au-dessus de 1,6 V (Pi 1-3 Zero) ou 2,0 V (Pi 4), « bas » en dessous de 0,9 V ou 0,8 V.
  • Résistances de tirage internes, activables par logiciel : 50 à 65 kΩ (Pi 1-3 Zero), 33 à 73 kΩ (Pi 4). GPIO2 et GPIO3 ont un tirage fixe vers 3,3 V (bus I²C).
  • À la mise sous tension, toutes les broches sont des entrées.
  • GPIO0 et GPIO1 (broches 27, 28) : réservées à l’EEPROM d’identification des HAT.

Lire une entrée : tirage et rebonds

  • Une entrée reliée à rien flotte : elle lit 0 ou 1 au hasard. Une résistance de tirage lui donne un état de repos.
  • Tirage vers le haut (pull-up) : repos = 1, bouton câblé vers la masse ; l’appui donne 0. C’est le choix par défaut de GPIO Zero : Button(27).
  • Tirage vers le bas (pull-down) : repos = 0, bouton câblé vers le 3,3 V : Button(27, pull_up=False).
  • Un contact mécanique rebondit quelques millisecondes : un appui peut compter double. Filtre logiciel : Button(27, bounce_time=0.05).

Loi d’Ohm en pratique

U = R × I (volts = ohms × ampères) · P = U × I (watts).

Résistance d’une LED sur 3,3 V

R = (3,3 V − tension de la LED) ÷ courant voulu. Pour 5 mA :

LED rouge (≈ 2,0 V)260 Ω → 270 Ω
LED bleue ou blanche (≈ 3,0 V)60 Ω → 68 Ω, éclat faible

En pratique, 220 à 330 Ω conviennent : 330 Ω sur une LED rouge donnent 3,9 mA. Tensions typiques : lire la fiche du composant.

Code couleur des résistances

0 noir1 marron2 rouge3 orange4 jaune5 vert6 bleu7 violet8 gris9 blanc

Deux chiffres, puis le nombre de zéros ; 4e anneau : tolérance (or 5 %, argent 10 %). 330 Ω : orange, orange, marron · 1 kΩ : marron, noir, rouge · 10 kΩ : marron, noir, orange.

Platine d’essai

  • Chaque rangée de 5 trous est reliée ; la rainure centrale sépare les deux moitiés.
  • Les rails du bord (+ et −) courent sur la longueur ; sur certaines platines, ils sont coupés au milieu.
  • Relier un rail à une broche GND du Pi, l’autre au 3,3 V (broche 1 ou 17).
  • Patte longue de la LED = anode (+), patte courte et méplat = cathode (−).

Adapter les tensions

  • Sortie 5 V d’un capteur (ex. écho du HC-SR04) → pont diviseur : 1 kΩ en série, 2 kΩ vers la masse → 5 × 2 / 3 = 3,33 V.
  • Bus I²C ou série en 5 V → convertisseur de niveaux bidirectionnel.
  • Tension analogique (potentiomètre, photorésistance) : le Pi n’a pas de convertisseur analogique-numérique → puce MCP3008 en SPI.

Commander une charge

  • Plus de 16 mA (relais, LED de puissance, buzzer) : transistor NPN ou MOSFET « niveau logique », commandé par la broche à travers ≈ 1 kΩ.
  • ! Diode de roue libre (ex. 1N4007) aux bornes de toute bobine : relais, moteur, électro-aimant.
  • Moteur à courant continu : pont en H (carte de commande) ; servomoteur : 5 V séparé, signal sur une broche PWM.
  • Toujours relier les masses du Pi et de l’alimentation extérieure.

Le multimètre, premier outil

  • Tension (V, courant continu) : pointes en parallèle, circuit alimenté ; une broche GPIO haute lit ≈ 3,3 V.
  • Continuité (bip) et résistance (Ω) : circuit hors tension, composant de préférence dessoudé.
  • ! Courant (A) : l’appareil se place en série ; jamais en parallèle sur une alimentation (fusible grillé, voire pire).
  • Commencer par le calibre le plus élevé, puis descendre.

PWM : doser sans convertisseur

  • La modulation de largeur d’impulsion (PWM) allume et éteint la broche très vite ; la part du temps à l’état haut (rapport cyclique, de 0 à 100 %) règle la puissance moyenne.
  • Usages : luminosité d’une LED (PWMLED), vitesse d’un moteur (par un pont en H), son d’un buzzer passif.
  • Servomoteur : une impulsion de 1 à 2 ms toutes les 20 ms fixe l’angle (valeurs par défaut de Servo et AngularServo ; à ajuster selon le modèle).
  • PWM matériel (GPIO 12, 13, 18, 19) : plus stable qu’un PWM logiciel pour un servomoteur.

Le Pi ne démarre pas : dans l’ordre

  1. Aucune DEL : alimentation, câble, prise ; retirer tous les accessoires, HAT compris.
  2. DEL allumée, rien d’autre : pas de système lisible → réécrire la carte avec Imager, essayer une autre carte.
  3. DEL verte qui clignote selon un motif : lire le code ci-dessous.
  4. Démarre, mais écran noir : écran sur HDMI0, bonne entrée choisie sur l’écran, autre câble ; tenter une connexion SSH.
  5. Redémarrages spontanés : sous-tension probable → vcgencmd get_throttled.

Sauvegarder

  • Ses fichiers : rsync -av ~/ moi@serveur:sauve-pi/, ou copie sur clé USB.
  • La carte entière, depuis le Pi : SD Card Copier (menu › Accessoires) vers une carte placée dans un lecteur USB.
  • Depuis un PC Linux : sudo dd if=/dev/sdX of=pi.img bs=4M status=progress ! vérifier sdX avec lsblk : une erreur de disque est sans appel.
  • Depuis Windows : un logiciel de lecture d’image disque (ex. Win32 Disk Imager).
  • Vérifier une fois la restauration : une sauvegarde jamais relue n’en est pas une.

Repartir de zéro

  1. Sauver ses fichiers (dossier personnel, config.txt modifié, scripts, fichiers de service).
  2. Réécrire Raspberry Pi OS avec Imager, en reprenant la même personnalisation.
  3. Sur l’ordinateur : ssh-keygen -R hôte.local (le Pi a changé d’empreinte).
  4. Remettre ses fichiers, réinstaller ses paquets, réactiver ses services.

Tenir un carnet de bord (commandes passées, fichiers modifiés) rend cette opération rapide.
